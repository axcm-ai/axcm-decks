Stack ›

Three tools that work together. Two are Google products; GitHub is separate (owned by Microsoft) and is the industry standard place to store website files.

GitHub

Typical cost: Free for a public site repo

  • What it is: online folder + history for every website file
  • Why it matters: every change is saved; easy to roll back
  • Who uses it day to day: AI (with Lance’s setup); Cory rarely needs to open it
  • Paid plans: only if private team features are needed later (~$4+/user/month) — not required for this public-site path

Firebase Hosting (Google)

Typical cost: Free Spark plan is enough for most marketing sites

  • What it is: puts the site on the internet with HTTPS and a custom domain
  • Free tier includes: storage and bandwidth suited to a normal company brochure site
  • Paid (Blaze): only if traffic grows far past the free limits (pay for overage)
  • Custom domain: supported on the free plan
    • Example for AMM: https://assurancemm.com

Workflow ›

This is not “Cory learns to code.” It is “Cory directs AI the way you’d brief a design lead.”

1
Brief AI (minutes)
  • Cory says what needs to change (example: “refresh the homepage hero and add a clearer Services section”).
  • No wireframing tools required.
  • No HTML or CSS knowledge required.
2
AI does the heavy lifting
  • Acts as web-design lead: proposes layout, imagery direction, and copy options.
  • Can research the live site and comparable medication-management / healthcare marketing sites.
  • Can run light competitive and messaging analysis so the page sounds current and clear.
  • Drafts the actual page updates (structure and wording).
  • Cory reviews in plain language: “keep A, change B, make the headline shorter.”
3
Preview
  • AI (or Lance on the first walkthrough) shows a private preview link.
  • Cory checks it on phone and desktop.
  • Nothing public changes until Cory says yes.
4
Publish
  • Approved changes go to Firebase Hosting.
  • www.assurancemedicationmanagement.com updates.
  • GitHub keeps a history so yesterday’s version can be restored if needed.
5
Iterate
  • Same loop for the next tweak.
  • Small changes can ship the same day.
  • No portal release cycle and no waiting on an outside builder for routine edits.

Web Dev Lead Agent — use cases

  • “Compare our Services page to three competitors and suggest a clearer outline.”
  • “Rewrite this section for patients’ families — 8th-grade reading level.”
  • “Propose a mobile-first homepage and show me two options.”
  • “Find broken or outdated wording on the current public site and fix it.”

Cory stays in charge of taste and approvals. AI handles research, drafting, and the mechanical build steps.

Outcomes ›
  • Ownership: Cory can direct site changes without opening a ticket to an outside builder for every edit.
  • Speed: preview first, then publish; many updates same-day.
  • Safety: history in GitHub; easy to roll back.
  • Discoverability: fast static pages that work well with Google search.
  • Low effort: Cory’s time is mostly briefing and approving — not clicking through developer tools.
